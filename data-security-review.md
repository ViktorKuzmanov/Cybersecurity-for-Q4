# Data security review: can someone copy our data?

**Date:** 19 Nov 2026 · **Scope:** website, API, MCP (`/mcp`), chat, files (Vercel Blob), logins, internal access, PDPL · **Related:** DD-66, DD-67, DD-68, DD-70

**How this was checked:** code review of `main` as of 19 Nov 2026 (commit `9d827b61`), plus a few light, read-only requests to **preview** (preview.q4.sa / preview-api.q4.sa, Development database). There was no load testing, no Production testing beyond one normal page load, no accounts were created, and no client data was used. Exact reproduction steps went to Filip separately.

## Short answer

Yes, it is easy today. A logged-out script can copy every earnings-call transcript (with our AI summaries) and nearly every PDF we hold. Anyone can make their own free account in a minute, and that account sees the financials and gets unlimited chat. Nothing on the site slows down a scraper.

The first four rows close most of the gap. Each one is a small code or config change.

## Risks, ranked

| # | Risk | How bad | How we tested it | Suggested fix |
|---|------|---------|------------------|---------------|
| 1 | **Free sign-ups get our data, and expired ones get the website too.** The public MCP sign-up page (`/mcp/oauth/checkout`) creates an account with any email (never verified) and a 6-character password, and **immediately starts a 31-day free MCP trial** with no card. A new email gives a new trial, so the free access never has to end. While the trial runs, the website correctly blocks the account ("This account is MCP only"). **When the trial ends**, `hasMcpAccess` turns false, so the account is no longer "MCP-only", and `auth-q4` never checks that the account has paid: the expired account **gets the full website and unlimited chat on any model**. The chat cap applies only to Freemium. Expired or cancelled paid accounts get the same access (**DD-67**). | **High** | **Live on preview (21 Nov):** a new sign-up through the Claude connector got MCP tools connected with no payment, and the tools return company data. **One** `q4_screen` call from the trial account returned verified FY 2025 net income for **350 of 413 companies** (about 470 KB, not truncated), each with a citation and a public Blob PDF link (see risk 3). Logging in on preview.q4.sa showed "This account is MCP only", so the trial is blocked from the website as intended. **Code:** `lib/subscription.js` (`startMcpTrial`, 31 days; `isMcpOnlyUser`), `middleware/auth-q4.js`, `support/model-access.js` (`freemiumDailyLimitForUser`). The after-expiry step can't be tested live without waiting 31 days, or setting the test account's expiry date on the Development database. | In `auth-q4`, require `hasPlatformAccess(user)` and return 402/403 otherwise, so expired, pending and trial-ended accounts are all blocked. Require email verification before a trial starts, and allow one trial per card or company domain. Cap chat for non-paying accounts. Add a test for each status. |
| 2 | **Transcripts, AI summaries and document lists are open without login.** `GET /api/q4/earning-calls/:id` returns the full transcript, utterances, summary, AI insights and file links. IDs are sequential numbers, and the public sitemap lists all **454** earnings-call pages. `/companies/:id/documents`, `/search/transcripts` (50 snippets per call), `/stock-history` and `/news/archive` are open too. | **High** | Logged out on preview: an earnings call returned 200 with a 1 MB body (28,761-character transcript, summary, insights). The document lists for 4 companies returned 1,266 documents. `/financials` and `/source-facts` correctly returned 401. Copying all transcripts takes about 454 requests, a few minutes. | Put `auth` on these routes. For SEO, give logged-out visitors a short preview (title, date, first paragraph) from a separate public endpoint. Stop listing every transcript in the sitemap, or link only the previews. |
| 3 | **Our PDFs sit in a public Blob store with permanent links.** Of the 1,266 document links above, **1,231 are public Blob URLs**. Each one opens with no login, has a 30-day public cache, and never expires. Once a link is copied, it works for anyone, forever. Imports (`scripts/import-argaam-documents.js`, the sync scripts) write `access: "public"` with predictable paths. Recordings (`audioUrl`) are private, which is correct. | **High** | `HEAD` on a public URL with no cookies: 200, `application/pdf`, `cache-control: public, max-age=2592000`. A private URL: 403. | Upload new files as `private`. Move existing ones to the private store. Always serve files through `/api/q4/documents/:id/file`, which already checks login, and stop sending the raw `url` to the browser. Keep the default `--access private` in the new Argaam upload script. |
| 4 | **Any `*.vercel.app` site can read a signed-in user's data (DD-68).** CORS allows any `https://*.vercel.app` origin with credentials, and the login cookie is `SameSite=None`. Anyone can deploy a free Vercel page, send a customer the link, and read whatever that customer can see. `/mcp` also reflects any origin with credentials. | **High** | Preview, `Origin: https://some-attacker-app.vercel.app` → `access-control-allow-origin` echoed back with `allow-credentials: true`. Same result on `/mcp` with `https://evil.example`. | Delete the `*.vercel.app` rule in `lib/allowed-origins.js` and list our own preview hosts. On `/mcp`, drop `credentials: true`, because MCP uses Bearer tokens, not cookies. |
| 5 | **Webhooks trust anyone when their secret is missing (DD-68).** The Stream payment webhook skips the signature check if `STREAM_WEBHOOK_SECRET` is not set, and that webhook **activates paid subscriptions**. The Recall webhook does the same with `RECALL_WEBHOOK_SECRET`. | **High if a secret is unset in Production**, otherwise Low | Code: `stream-pay.service.js` (`verifyStreamWebhookSignature` returns ok when there is no secret), `recall-webhook.controller.js`. I could not see the Production env vars. | Check both secrets in the Vercel Production env today. Change the code to fail closed: reject the request when the secret is missing. |
| 6 | **Nothing slows down scrapers.** There is no Cloudflare and no visible Vercel Firewall rule. The API has no per-IP rate limit (only the MCP, password-reset and share endpoints have limits). | **Medium** | Preview: 25 back-to-back requests with a `python-requests` user agent were all served, with no 429 and no challenge. Production headers show only `server: Vercel`, with no firewall or mitigation headers. | Turn on Vercel Firewall bot protection and add a rate-limit rule on `/api/q4/*` (e.g. 60/min per IP for logged-out visitors). Alert on accounts that read an unusual number of companies per day. |
| 7 | **One MCP/API account can download almost everything.** The limit is 60 calls/min per user, **kept in memory per server instance**, so it resets on cold start and multiplies across instances. There is no daily cap. `q4_screen` returns up to 400 companies × 12 columns per call, and `q4_get_earnings_call` takes up to 5,000 sentences (a whole transcript). A paid key could copy all figures and transcripts in about an hour. | **Medium** | Code: `mcp/rate-limit.js`, `mcp/attach-mcp.js`, `mcp/schemas.js`. | Store a daily quota per user in the database (calls and companies per day). Lower `q4_screen` to about 50 companies per call for normal plans. Log and alert on heavy use. |
| 8 | **Chat can be asked to dump tables.** `q4_query` returns up to 400 rows per result, and `q4_python` reads up to 20,000 rows. Results become tables the user can export to Excel. The prompt itself says that a question about all companies gets all of them in the table. Together with risk 1, this is a free bulk export. | **Medium** | Code: `chat-v3/connect/general-tools.js` (`MAX_ROWS = 400`, `MAX_PYTHON_ROWS = 20000`, prompt text). The SQL guard itself is solid: only the `q4` chat tables, SELECT only, an allow-list of functions, parsed with the real Postgres parser. Users, chats and keys cannot be reached. | Cap the rows shown per answer for normal plans (e.g. 50), with full tables only for paying or enterprise accounts. Add a daily row budget per user. Flag "all companies / all figures" requests in analytics. |
| 9 | **Login gaps (DD-66).** There is no rate limit on `/api/auth/login`, the minimum password length is 6 characters, and tokens last 7 days with no way to revoke them (logout clears only the cookie). Every API route also accepts the token in the URL (`?token=` / `?access_token=`), where it ends up in logs and browser history. The web app keeps the JWT in `localStorage`, so one XSS bug would leak it. | **Medium** | Preview: 8 wrong logins in a row all returned 400, with no 429. Code: `auth.controller.js`, `middleware/auth.js`, `optional-auth.js`. The current frontend does not put the login token in URLs. The Excel file links use a separate short-lived token, which is fine. | Rate-limit login per IP and per email (the `checkRateLimit` helper already exists). Require at least 10 characters. Add `tokenVersion` to users so logout and password changes revoke old tokens. Remove query-string tokens from `auth.js` and `optional-auth.js`. |
| 10 | **Internal access is wide.** Prisma Postgres has no read-only roles, so every connection string can do everything (the chat's included). The Development database is a nightly copy of Production, so Development access means Production data. 22 workflow steps use `PRODUCTION_DATABASE_URL`, and `BLOB_READ_WRITE_TOKEN` (full read and write on Blob) appears in 16. | **Medium** | Repo config: `.github/workflows/*`, the `sql-guard.js` header comment. **Not checked:** who is a member of the Vercel team, the Prisma project and the GitHub org, and when keys were last rotated. I had no admin access to those. | An admin lists members of Vercel, Prisma, GitHub (and the `production` environment reviewers) and removes anyone who no longer needs access. Rotate `JWT_SECRET`, the DB passwords and the Blob tokens, and write the date down. Give jobs separate Blob tokens per store. |
| 11 | **Where the data lives (DD-70, PDPL).** The API runs in Vercel `iad1` (US East): there is no `regions` in `vercel.json`, and the response header shows `iad1`. The Blob and Postgres regions were not confirmed. The PDPL section of our DPA says "reserved". Market data is public, but user accounts, emails and chat questions are personal data. | **Low now, check with DD-70** | Response header `x-vercel-id`, `Backend/vercel.json`, the DPA page in the frontend. | Record the region of each store in DD-70. Decide with legal whether personal data must move to a KSA or GCC region. |

## What is already fine

- Financial figures (`/financials`, `/source-facts`) and the file proxy (`/documents/:id/file`) require login.
- Recordings and uploaded meeting files are in the private Blob store, and private URLs return 403.
- The chat SQL tool cannot reach users, chats, API keys or system tables.
- Password-reset links are single-use and expire after 30 minutes. Slack and GitHub webhooks verify their signatures.
- Production DB secrets in GitHub sit behind the `production` environment (only `main` can use them).
